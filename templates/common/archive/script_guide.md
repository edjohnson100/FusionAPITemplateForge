# Fusion Script Template — User Guide

This project was generated by Fusion API Template Forge, so the mechanical rename/GUID/manifest work the original template normally requires is already done. See `NEXT_STEPS.md` for the one remaining manual step (loading it into Fusion). What's left is the actual feature conversation below.

## The feature conversation

Don't make the assistant interview you. Explain the project like you would to a person: what it does, roughly how (sketch it, extrude it, whatever the actual operation is), and any Fusion-specific constraints you already know (needs Hybrid design intent, needs a specific workspace, etc.).

Unlike an add-in, there's no toolbar placement or tab layout to decide up front — a script has no persistent UI. It runs once from `run(context)` and exits. If it needs input, that's a one-shot `ui.createFileDialog()`, `ui.inputBox()`, or a single `adsk.core.CommandCreatedEventArgs` dialog you build for the occasion — not a config manager or theme system, since those only make sense for something that stays open across sessions.

Everything else — error handling shape, whether to log to the Text Command window via `app.log(...)`, how much of the operation to wrap in one undo-friendly transaction — is a judgment call the assistant can make from your description. It doesn't need a formal Q&A pass for that; just push back if something looks wrong once you see the plan.
